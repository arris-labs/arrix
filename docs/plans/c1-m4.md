# Plan: c1-m4

- Started: 2026-10-08
- Cycle: C1, M4 (exchange and batch evaluation), closing the cycle
- Idea: none; verbatim from the human: "/plan m4", the in-list and the
  cycle's accept in `docs/ROADMAP.md` §M4 and §C1

## Goal
C1's accept runs green, in `cargo test` and in `arrix eval` on its saved
document. A bracket built through the commands the UI issues (plate,
pocket, filleted edges, a linear pattern of counterbored holes, a spur gear
joined and an edge of its face filleted downstream) matches its golden JSON,
survives a width edit with no lost reference, saves to identical bytes,
reopens without `gears` with the gear frozen and the fillet on it still
evaluated, fails a too-large fillet with its category and a recipe, exports
STEP that `arris_io::step::read` reads back and closed STL and OBJ, and
sweeps its width over 50 values with a failure histogram. `arrix eval` is
complete: many documents and directories, `--sweep`, `--summary`,
`--timings`, `--jobs` and `--budget`. A superseded evaluation stops inside
a kernel call through Arris's `Control` (A3, in the pinned `arris` 0.5).
The budgets of `docs/CONCURRENCY-WASM.md` §Budgets are measured on the
acceptance part and written there. `/close-cycle` can then run.

## Non-goals
- Taking `arris` 0.6 (`cut_many`, per-face tessellation, `split`, `shell`):
  M4 needs nothing from it; the bump is its own change.
- Exporters as a plugin contribution point (`docs/PLUGINS.md` §4) and the
  robotics exporters: STEP, STL and OBJ are core exchange (`SEED.md` §6.2's
  table) and go through `arrix-kernel`. Plugin exporters wait for a plugin
  that needs one (the robotics plugin, by C3).
- STEP import, 3MF, DXF/SVG, assembly structure in STEP (C2, A4).
- Parallel evaluation inside one document; `--jobs` is across documents.
- A wall-clock timeout in `arrix eval`; only the deterministic step budget.
- Fixing a budget the benchmark finds missed: a miss is written down with
  its number and becomes a `docs/BACKLOG.md` line, not a step here.
- The backlog's display bugs from M3 (stale bodies after a failed
  modifier, the speck under a first preview).

## Design deltas
- **ADR-0020, a persistent name into a consumed slot follows its
  consumer** (amends ADR-0007's consumed-slot rule for `Topo` names only).
  A name whose slot a feature consumed resolves in the slot that feature
  modified, as of the reader; found there, it reads; not found, it is
  `slot.consumed` as now. A body input on a consumed slot stays
  `slot.consumed`. This is what lets the cycle's accept fillet an edge of
  the joined gear (the `docs/BACKLOG.md` line from `plans/m3-accept` step
  2, removed by step 1). `docs/DATA-MODEL.md` §Bodies across features.
- **Cancellation inside a kernel call.** The `Kernel` owns an interrupt
  flag (`Arc<AtomicBool>`, no clock, wasm-clean) and passes
  `Control::poll` over it to every Arris call it makes; the evaluator's
  worker raises it when a newer snapshot is queued and lowers it before the
  next feature. An interrupted call is `kernel.interrupted`: the feature
  publishes no event, caches nothing, and the worker starts over on the
  newest snapshot. `docs/CONCURRENCY-WASM.md` §The evaluator,
  `docs/ARCHITECTURE.md` §The kernel choke point.
- **The step budget.** `Kernel::set_budget(Option<u64>)`, a budget per
  kernel call (`Control::with_budget`), so a result depends only on the
  document and the number. A call it stops fails as
  `kernel.interrupted.budget`, a category like any other in the summary,
  and the poll's stop stays `kernel.interrupted`.
- **Export in the kernel.** `Kernel::export_step(&[KernelBody]) ->
  String` (`arris_io::step::write`), `export_stl` and `export_obj` of the
  bodies' refined meshes (`arris_io::stl::write_binary`, `obj::write`), each
  a recorded `KernelCall` (`KernelOp::Export { format, bodies }`) with a
  `kernel.export.<error>` category. Frozen bodies export like any other.
- **Export in the protocol.** `Request::Export { bodies, format }` (empty
  `bodies`: every final body) answered by `SessionEvent::Exported {
  generation, format, bytes }` or a diagnostic, run on the evaluator thread
  after the newest commit is evaluated; plain data like every other
  request (`docs/ARCHITECTURE.md` §The protocol boundary). No document
  change, so no command and no gesture.
- **`arrix export <doc> --format step|stl|obj [--body <feature>.<slot>]…
  -o <file>`**, the headless path through `arrix_doc::export`
  (`docs/ARCHITECTURE.md` §Crates already lists `export` for the CLI).
- **`arrix eval` complete** as `docs/CONCURRENCY-WASM.md` §Batch evaluation
  states it: several paths; a directory holding `document.json` is a
  document, any other is searched for `.arrx` files and document
  directories, sorted by path; one line per document in that order, whatever
  `--jobs` is. `--sweep <param>=<from>..<to>:<n>` on a document parameter,
  and `<feature>.<field>` on a feature's numeric field (the feature by its
  name or id), `from` and `to` expressions, each point a parameter edit on
  one evaluator so the cache carries over; the line's `sweep` is `{"target",
  "index", "value"}`. `--summary` and `--timings` as that section says; the summary a last JSON line.
- **The app's export**: a `file.export` command in the registry
  and palette, a native save dialog (`crates/arrix-app/src/file_dialog`),
  the format from the extension, the selected bodies or, with none
  selected, every body.
- No schema bump, no migration: nothing the document persists changes.
- `arrix-plugin-api`: no change. A plugin's kernel calls go through the same
  `Kernel`, so they are interrupted and budgeted with no API surface.

## Arris dependencies
All in the pinned `arris` 0.5:
- A3 cancellation: `arris::Control` (`poll`, `budget`, `with_budget`),
  `OpError::Interrupted`, `MeshError::Interrupted`,
  `BodyError::Interrupted`; released in 0.4.0 (Arris ADR-0030). ArriX's
  docs still list A3 as "asked"; step 2 corrects them.
- `arris_io::step::write(model, bodies)` and `step::read(model, text,
  options, control)` for the round trip.
- `arris_io::stl::write_binary(meshes, name)`, `arris_io::obj::write(meshes)`
  over `TriMesh` from `arris::mesh::tessellate_with`.
- `measure::mass_properties` for the read-back volume.

No ask is needed. A failure the bracket meets in Arris (a refusal of a
shape the accept needs) is filed as a fixture and the scenario waits; it is
not reshaped around it silently, and a reshaping is the human's call.

## Open questions
Settled by the human on 2026-10-08, each as recommended:
1. The summary is a last JSON line on stdout,
   `{"summary":[{"category","count","docs","plugins"}]}`.
2. The budget is per kernel call.
3. The app's export stays in M4 (step 7).
4. ADR-0020's rule: a name into a consumed slot follows its consumer; no
   new step in a joined tool's names.

Findings:
- Step 6: the layer rule keeps Arris out of `arrix-cli`, so the read-back
  of a STEP is `arrix_kernel::read_step` (faces, edges, vertices and volume
  per solid). A body is named by the feature that made it, so `--body` takes
  that feature's id or name, not the last feature's. A failed modifier leaves
  no final body (the M3 backlog line), so a document whose pocket fails
  exports nothing (exit 2, `export.no-bodies`); exit 1 is a failure that
  leaves the bodies alone (a bad parameter).
- Step 1: most of the slice gear's edges do not fillet alone. Of its
  start-face edges at 0.3 mm, 20 (one per tooth) fillet, 200 are
  `kernel.degenerate.blend-too-large` ("the blend leaves its face through
  an edge that is not the corner's own"), and 20 are `kernel.unsupported`
  (no closed form for a cylinder against a cylinder). Every one of its 240
  end-face edges fails, even at 0.05 mm. Step 13 picks the gear edge it
  fillets from the ones that work
  (`crates/arrix-cli/tests/frozen_faces.rs` uses `start-edge…KH3`). Whether
  the end-face failures are a kernel gap worth a recipe is for step 13 to
  find out.
- Step 2: the poll reaches every call, and a raise stops a 0.4 s fillet
  over 256 hole edges about half a millisecond later, the model rolled
  back (`crates/arrix-kernel/tests/interrupt.rs`). An interrupted call is
  one category whatever its kind: the mesh's and the body bytes'
  `interrupted` became `kernel.interrupted` (`.budget` for a spent
  budget). Its record replays to success, so step 12 keeps a
  `kernel.interrupted.budget` failure out of `--save-fixtures`.
- Step 4: `KernelOp::Export { format }` carries no `bodies`: the bodies are
  the call's operands, already recorded by hash and by source call, and a
  second list would only repeat them. `ExportFormat` is in `arrix-core`
  (step 5's request and step 7's dialog name it too). **Units:** Arris
  0.5's `step::write` declares lengths in millimetres and writes the
  model's numbers unchanged, and ArriX's model is in metres, so the STEP
  (and the STL and OBJ, written in metres too) of a 20 mm plate carries
  0.02. The round trip through `step::read` (millimetres by default, also
  unchanged) is exact, so the step's tests cannot see it. ⚠ OPEN: the unit
  of ArriX's exchange files, for the human: STEP needs an Arris ask (a
  length unit on the writer, or a uniform scale), the meshes could be
  scaled here at once. `docs/BACKLOG.md` has the line; steps 5 to 7 and 15
  carry on with metres, so the change stays in `arrix-kernel`.
- Step 5: the request is answered by a new `Outcome::Exporting` (the
  other answers say a command applied, or nothing did, or a preview was
  taken), and `Session::export` is the helper beside `preview`. The
  file is an event to every subscriber, as every other result is. An
  export runs behind the newest commit and before a waiting preview, and
  evaluates that commit again, cache-warm, when a preview has run since.
- Step 7: `rfd` 0.15 (XDG portal backend, no GTK) is the native dialog,
  target-gated off wasm, where the dialog answers cancelled until C4's
  download. The scenario is `tests/visual/export.rs`, not a logic test,
  because the selection's bodies come from the scene, which only a renderer
  fills.
