# Plan: c1-m0

- Started: 2026-09-26
- Cycle: C1, milestone M0 (`docs/ROADMAP.md` §M0 — the gate and the harness)
- Idea: none; verbatim from the roadmap's M0 in-list

## Goal

The workspace exists with every crate of `docs/ARCHITECTURE.md` §Crates
compiling, native and `wasm32-unknown-unknown`, and `arrix-core` holds
units and quantities, ids and `Diagnostic`. Every commit from the second
step on passes through the gate: `.githooks/pre-commit` (fmt, clippy, size,
wasm and layer lints) and `pre-push` (tests, all-features tests, the wasm
build), mirrored by CI, each lint proven to fail on a deliberate violation.
The headless visual harness is ported onto an empty shell (ribbon, tree,
viewport, property panel, status bar): one snapshot scenario whose golden
is text (`debug_state()` and the coarse frame, ADR-0001), images rendered
on demand by `scripts/snapshot-baseline`, the scratch render and the
`visual-debug` skill. `arrix eval` reads an empty document directory and
prints its JSON line, pinned by a golden. `AGENTS.md` §Commands lists how to
run all of it.

## Non-goals

- No document model beyond what reading an empty directory needs: no
  parameters, parts, features, commands, undo, sessions, evaluator, zip
  form or migrations (M1). `document.json` is read and its schema checked;
  nothing else is interpreted.
- No `Ref`, `PersistentName` or naming types (M1–M2). `Diagnostic` gets
  its `refs` and `candidates` fields with `Ref` in M1.
- No kernel call. `arrix-kernel` depends on `arris` so the layer lint has
  something to hold, and exposes nothing yet.
- No viewport port: the shell's viewport is an empty egui region. The wgpu
  scene, picking and camera are M3's port; the harness still renders the
  whole frame through wgpu.
- No command registry, palette or forms: the ribbon shows its two core tabs
  with no buttons (M3).
- No `arrix eval` flags (`--sweep`, `--summary`, …; M4). No network code,
  no push: CI is written, and runs when the human pushes.

## Design deltas

- `docs/ARCHITECTURE.md` §Crates: the table becomes true, with the pinned
  external versions (`arris` 0.2, `egui`/`eframe`/`egui-wgpu`/`egui_kittest`
  0.36) and a `plugins/gears` stub depending on `arrix-plugin-api` only.
  §Gates: the list becomes exact (script names, what each checks, where its
  allowlists live, the lint self-test). The opening "nothing here is built
  yet" narrows to what is still unbuilt.
- `docs/ARCHITECTURE.md` §Errors and diagnostics: `Diagnostic` as built in
  M0 (severity, a stable code with its grammar, message); refs and
  candidates named as M1's.
- `docs/DATA-MODEL.md` §Identifiers: the id type as built: 64 bits, 13
  Crockford base32 characters, a serde string, a minter the caller seeds
  (so `arrix-core` reads no entropy source and stays deterministic and
  wasm-clean; where the seed comes from is the client's, M1). §File
  format: the empty directory form that opens today (`document.json` with
  `schema: 1`), and that a newer schema is refused.
- `docs/UI-RENDERING.md` §Visual debugging: the paths and knobs as built
  (golden format, cell size, tolerance and budget defaults, the env
  variables, the baseline script's outputs). §View types: the shell's
  first view types (`RibbonView`, `TreeView`, `StatusView`, and the empty
  property panel) as built.
- `docs/CONCURRENCY-WASM.md` §Batch evaluation: `arrix eval` on a single
  directory, exit codes 0 and 2 in force; the rest of the flags M4's.
- `AGENTS.md` §Commands and §Setup: the gate, the hooks line, the snapshot
  and scratch commands, `arrix eval`.
- No ADR is expected: every decision here is already in `SEED.md`, the
  design docs or ADR-0001. If the coarse frame's defaults turn out to need
  a different shape than ADR-0001 states (step 6), that is an ADR.
- No persisted document schema changes beyond defining v1's
  `document.json` header; no `arrix-plugin-api` surface (the crate is an
  empty 0.0.0 stub, so no semver effect).

## Arris dependencies

- `arris` 0.2.0 from crates.io, as a dependency of `arrix-kernel` only. No
  API is called in M0. Arris's own CI builds its workspace for
  `wasm32-unknown-unknown`; step 1 confirms 0.2.0 does in ours.
- No ask (A1–A11) is needed by M0.

## Steps

Complexity: **[1]** routine — the design says what to write, the tests are
mechanical; **[2]** careful — a case to get right within a given design;
**[3]** unproven — behaviour that has to be established here.

- [x] **[1]** Step 1 — **The workspace.** Root `Cargo.toml` (edition 2024,
  resolver 3, `[workspace.dependencies]` with pinned minors), a
  `rust-toolchain.toml` (stable, `rustfmt`, `clippy`, the wasm32 target),
  and every crate of §Crates as a `#![forbid(unsafe_code)]` stub with its
  allowed workspace edges only: `arrix-core`, `-kernel` (with `arris`),
  `-sketch`, `-plugin-api`, `-doc`, `-plugin-host`, `-viewport`, `-ui`,
  `-app` (a binary opening an empty eframe window), `-cli` (a `clap`
  binary with no subcommand yet), `plugins/gears`. *Observable:* `cargo
  build --workspace` and `cargo build --target wasm32-unknown-unknown
  --workspace --exclude arrix-cli` both succeed; `cargo test --workspace`
  runs (no tests yet). `ARCHITECTURE.md` §Crates updated with the versions.
- [ ] **[1]** Step 2 — **The hooks and the ported lints.**
  `.githooks/pre-commit` and `pre-push` exactly as §Gates lists them;
  `scripts/size-lint` and `scripts/wasm-lint` ported (Python 3, scanning
  `crates/` and `plugins/`; the wasm lint gains the `std::thread::spawn`
  and `std::fs` rules of §Gates, with the permitted paths in one table at
  the top of the script); `scripts/size-allowlist.txt` empty, its header
  requiring each entry to name the plan that removes it.
  `scripts/gate-selftest` started: it exports `HEAD` into a temporary
  directory, injects one violation per case, and asserts that lint fails
  and passes on the clean copy. Cases here: an oversize function,
  `Instant::now` in `arrix-core`. `git config core.hooksPath .githooks`
  run; `AGENTS.md` §Setup and §Commands name the hooks and the lints.
  *Observable:* `scripts/gate-selftest` green; this commit is the first to
  pass through `pre-commit`.
- [ ] **[2]** Step 3 — **The layer lint.** `scripts/layer-lint`: the
  dependency edges per crate from `cargo metadata --no-deps` against the
  allowed-edges table of §Crates (a plugin with any `arrix-*` but
  `arrix-plugin-api`; `arris` outside `arrix-kernel`; `egui`, `eframe`,
  `wgpu`, `egui-wgpu` outside viewport/ui/app; `arrix-doc` or
  `arrix-sketch` reachable from `arrix-ui`), plus a scan of `use` and path
  expressions as written (`arris::`, `egui::`, `arrix_doc`,
  `arrix_sketch`, any `arrix_*` but `arrix_plugin_api` in `plugins/`),
  comments and strings stripped as the size lint does. Case to get right:
  a re-export (`arrix-ui` naming a doc type through another crate), which
  the edge check catches because `arrix-ui` may not depend on a crate that
  depends on `arrix-doc`. Added to `pre-commit` and to the self-test with
  the cases `egui` in `arrix-doc` and a second `arrix-*` dependency in
  `plugins/gears`. *Observable:* the four M0 violation cases each fail
  their lint in `scripts/gate-selftest`; the real tree passes.
- [ ] **[3]** Step 4 — **Probe: the empty shell, rendered headlessly.**
  The first view types in `arrix-ui` (`RibbonView` with the Sketch and Part
  tabs, `TreeView` with no parts, `StatusView` with generation, diagnostics
  count and display units) and their widgets; `arrix-app` lays out the
  shell of `docs/UI-RENDERING.md` §The shell from static views and exposes
  `debug_state()` (panel rects, the ribbon, the tree, the status, the
  window size; floats rounded to six places). The harness ported to
  `crates/arrix-app/tests/visual/harness.rs` (adapter probe that skips
  loudly, the GPU lock, settle and pump helpers), and the scratch target
  `visual_scratch` (`test = false`) writing
  `target/visual-scratch/scratch.{png,json}`. To establish: on lavapipe,
  two renders of the shell in one process and in two processes give
  identical PNGs (or, if not, how far apart, which step 5's tolerance must
  absorb), and nothing time-dependent reaches a pixel. *Observable:* the
  scratch PNG read by the agent shows the five regions; a test asserts the
  two renders' agreement found here.
- [ ] **[2]** Step 5 — **The coarse frame and the first scenario.** The
  golden format of ADR-0001 in the harness: `debug_state()` and the coarse
  frame (16×16 cells, mean RGB, one hex string per row) in one
  `crates/arrix-app/tests/snapshots/<name>.json`; comparison per cell with
  a tolerance and a cell budget, overridable per scenario; a failure names
  the differing cells as pixel rectangles and the first `debug_state()`
  difference; `UPDATE_SNAPSHOTS=1` rewrites; full frames always written to
  `target/snapshots/<name>.png`. Unit tests of the reduction and the
  comparison on synthetic images, no GPU: a one-cell change inside the
  tolerance passes, one outside fails and is named, a change over the
  budget fails. Scenario `empty_shell` pinned; its golden's text diff read
  before staging. *Observable:* `cargo test -p arrix-app --test visual`
  green on lavapipe; a deliberate colour change in the status bar fails it
  with the bar's rectangle named.
- [ ] **[2]** Step 6 — **Images on demand.** `scripts/snapshot-baseline
  [<rev>]` (default `HEAD`): a temporary `git worktree` at the revision,
  the visual scenarios run there with their frames directed to
  `target/snapshots/<name>.before.png`, then `<name>.diff.png` (differing
  pixels highlighted over a dimmed after-image) beside the current run's
  frame; the worktree removed on exit, even on failure. *Observable:* at
  `HEAD` on a clean tree every diff image is empty; with the status-bar
  change of step 5 uncommitted, the diff shows the bar only. The agent
  reads all three images.
- [ ] **[1]** Step 7 — **The `visual-debug` skill.** Ported to
  `.agents/skills/visual-debug/SKILL.md`, rewritten for ArriX: scratch vs
  scenario, reading the PNG and the JSON, the coarse frame and its knobs,
  `snapshot-baseline` before any golden refresh, the pitfalls of
  `docs/UI-RENDERING.md` §Visual debugging. It names no other project.
  *Observable:* the skill lists in a fresh session; each command it gives
  runs as written.
- [ ] **[1]** Step 8 — **`arrix-core`: units, ids, `Diagnostic`.**
  Quantity kinds (length, angle, count, ratio, mass) with SI values and a
  unit table (`mm`, `cm`, `m`, `in`, `deg`, `rad`, `g`, `kg`) converting
  to SI; typed ids (`PartId`, `FeatureId`, `ParamId`, `SketchEntityId`,
  `RecordId`) over one 64-bit `Id` written as 13 Crockford base32
  characters, parsed case-insensitively with the usual Crockford aliases,
  serde as that string; an `IdMinter` seeded by its caller; `PluginId` as
  a validated dotted-namespace string; `Diagnostic { severity, code,
  message }` with the code grammar (`segment(.segment)*`, lower-kebab)
  checked at construction. *Observable:* unit tests and `proptest` round
  trips (id ↔ string ↔ JSON; unit conversion); the same minter seed gives
  the same ids on native and in the wasm build (a compile check here; the
  value check is a native test with pinned expected ids).
- [ ] **[2]** Step 9 — **`arrix eval` on an empty document.** `arrix-doc`
  opens a document directory: reads `document.json`, accepts `schema: 1`,
  refuses a newer schema with a message naming both, and finds no parts.
  The JSON line type of `docs/CONCURRENCY-WASM.md` §Batch evaluation lives
  beside it, so tests and the CLI share one code path. `arrix eval <dir>`
  prints the line (`status: "ok"`, empty `features` and `bodies`), exit 0;
  a missing directory, malformed JSON or a newer schema exit 2 with a
  message on stderr. Scenario document `tests/docs/empty/` (unzipped form)
  and golden `crates/arrix-cli/tests/golden/eval_empty.jsonl`, compared
  byte for byte by an integration test that runs the binary. *Observable:*
  the golden test and the three exit-2 cases green.
- [ ] **[1]** Step 10 — **CI.** `.github/workflows/ci.yml` mirroring the
  hooks job for job: fmt, clippy, the three lints and `gate-selftest`,
  tests and all-features tests with `mesa-vulkan-drivers` installed (a
  visual scenario that skips in CI fails the job, since CI has an
  adapter), the wasm build; snapshot `target/snapshots/` uploaded as an
  artifact when the visual job fails. *Observable:* `actionlint` if
  available, else a YAML parse; each job's command list diffed against the
  hooks by a check in `gate-selftest`, so the two cannot drift. The first
  real run happens on the human's next push.
- [ ] **[1]** Step 11 — **The gate on a clean clone.** `git clone` of the
  repository into a temporary directory, `core.hooksPath` set, both hooks'
  command lists run there, `scripts/gate-selftest` run there; any gap
  (a file ignored locally, a toolchain component missing from
  `rust-toolchain.toml`) fixed in this step. `AGENTS.md` §Commands final;
  `ARCHITECTURE.md` §Gates exact. *Observable:* the acceptance below,
  recorded in the commit body.

Each step is one commit-sized unit with its own test or snapshot.

## Acceptance

Run on a fresh `git clone` of `main` in a temporary directory, with
`git config core.hooksPath .githooks`:

1. `.githooks/pre-commit` and `.githooks/pre-push` both exit 0 (fmt,
   clippy, size, wasm and layer lints; workspace tests with and without
   all features; the wasm build).
2. `scripts/gate-selftest` exits 0, having shown each of these fail its
   lint: an oversize function (size), `Instant::now` in a core crate
   (wasm), `egui` in `arrix-doc` (layer), a second `arrix-*` dependency in
   `plugins/gears` (layer).
3. `cargo test -p arrix-app --test visual` runs the `empty_shell` scenario
   on lavapipe against its text golden, and does not skip.
4. `cargo run -p arrix-cli -- eval tests/docs/empty` prints exactly the
   golden line and exits 0.

This is M0's accept in `docs/ROADMAP.md`; nothing is routed around it.

## Open questions

- ⚠ OPEN: lint language. The ported lints are Python 3 scripts; the layer
  lint could instead be a Rust `xtask` reading `cargo metadata` natively.
  Proposed: Python for all three, for one idiom and no build in
  `pre-commit`. Agent decides by step 2; the human may overrule.
- ⚠ OPEN: the coarse frame's tolerance and cell budget defaults. ADR-0001
  fixes the cell size (16 px) but not the numbers; step 4 measures
  lavapipe's run-to-run spread and step 5 sets the defaults from it. Agent
  decides by step 5, writes them into `UI-RENDERING.md`.
- ⚠ OPEN: `Diagnostic` without `refs` in M0. Proposed: add `refs` and
  `candidates` with `Ref` in M1 rather than a placeholder type now. Agent
  decides by step 8.
- ⚠ OPEN: CI is unverified until pushed. Step 10 makes the workflow and
  its drift check; the human decides when to push, and a red first run is
  fixed as a `ci:` commit before M1 starts.
