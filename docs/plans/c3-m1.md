- Cycle: C3, M1 (Tier 1); ADR-0034 details the cycle
- Idea: none. Verbatim from the human: "review c3 and rewrite if necessary

  `wit-bindgen`'s `export!` emits `unsafe`…", which step 1 removes.

## Goal

A Rust plugin written against `arrix-plugin-api` alone builds as a
WebAssembly component and runs at Tier 1 in a native ArriX: `arrix eval`,
`describe`, `test` and `serve`, and `arrix-app`, load it by `--plugin
<dir>` and `session.load_plugin`, reading the tier from its manifest.
`gears`, unchanged but for its export line, evaluates at Tier 1 to the same
bodies, names, eval line and saved bytes as at Tier 0, and a document made
at one tier opens live, not stale, at the other. The sandbox holds: the
only imports a component has are the world's, so one that imports anything
else is refused at load. A feature that loops ends on its fuel, the same
way every time. A feature that panics, traps or exhausts its memory ends as
that feature's diagnostic while the rest of the document evaluates. A
superseded evaluation stops a running component as it stops a kernel call.
The wasm32 build compiles without wasmtime, and there a Tier 1 plugin's
features are frozen with their reason. The risk retired: the component
model carries the world, the kernel's handles included, with nothing lost
between Tier 0 and Tier 1.

## Non-goals

- Any WIT change: the world stays 0.6's `kernel` import and `feature`
  export. The snapshot read and exporters are M2; commands are M3.
- `robotics`, `fasteners`, `arrix-plugin-test`, plugins as workspaces of
  their own, and the API's stability review: M2 and M3 (ADR-0034).
- Tier 1 in the browser (C4's ADR). There, a Tier 1 plugin's features are
  frozen.
- A Tier 1 plugin in any language but Rust. Anything that compiles to a
  component of the world loads, but only Rust is tested and documented.
- Capabilities beyond `kernel`: `document-read`, `document-write` and
  `files` have no import to grant until M2 and M3, and `network` is never
  granted.
- A cache of compiled components across runs (wasmtime's serialised
  modules), until a load budget asks for one.
- Unloading a plugin (backlog).

## Design deltas

- **ADR-0034** (step 1): C3's scope and milestones. It amends `SEED.md` §7
  (the C3 line) and §6.7 (`plugins/robotics` is Tier 1) and rewrites
  `docs/ROADMAP.md` §C3. It and the roadmap are already written into the
  tree beside this plan.
- **ADR-0035, Tier 1** (step 3), from step 2's probe:
  - *The guest SDK*: a `guest` feature of `arrix-plugin-api` with
    `arrix_plugin_api::export_plugin!(T)` over a `Feature`, built on the
    generated `Guest` adapter that `tests/wit_equality.rs` already holds.
    A plugin keeps the layer rule: it depends on `arrix-plugin-api` alone.
  - *Where the `unsafe` lives* (the absorbed backlog line): the workspace
    `forbid`s `unsafe_code`, and `forbid` cannot be allowed beneath. The
    probe finds the narrowest exception. The candidate: `arrix-plugin-api`
    at `deny` with only its `guest` module allowed, and `export_plugin!`
    expanding to safe code in the plugin's crate.
  - *Build and componentising*: either `wasm32-unknown-unknown` with the
    host componentising at load (`wit-component`, so an author needs only
    `cargo build`), or `wasm32-wasip2` with its WASI imports refused. The
    probe decides.
  - *The sandbox*: a store per evaluation from one `InstancePre` per
    plugin, so no state survives between evaluations. NaN
    canonicalisation is on. A component with an import outside the world
    is `plugin.load`. Fuel per evaluation (a default; the manifest may
    raise it) runs out as `plugin.fuel`, deterministically. A memory
    limit is `plugin.memory`. A trap or a guest panic is `plugin.trap`.
    `kernel = false` refuses each kernel call as `plugin.capability`, as
    Tier 2 does.
  - *Cancellation*: how the evaluator's interrupt flag
    (`docs/CONCURRENCY-WASM.md` §Cancellation, an `Arc<AtomicBool>`)
    reaches a running component. Either an epoch deadline callback that
    polls the flag, with the epoch ticked where the flag is raised, or
    fuel slices that check it. The flag is passed host-side (`arrix-doc`'s
    `FeatureArgs`), never through the API.
- **`arrix-plugin-api`** (step 4): the `guest` feature and
  `export_plugin!`. The Guest-over-`Feature` adapter moves from the test
  into the crate, and the test uses it. API: adds the `guest` feature; the world is
  unchanged and the WIT package version is the crate's, so both stay
  0.6.0 (step 4). `gears` gains `crate-type = ["rlib", "cdylib"]` and its
  `export_plugin!` under a `guest` feature of its own.
- **Manifest** (step 5, `docs/PLUGINS.md` §The manifest): a `[tier1]`
  table with `component`, a path inside the plugin's directory, and
  optional `fuel`. It is required on tier 1 and refused on any other
  tier, like `[tier2]`.
- **`arrix-plugin-host`** (steps 6 to 9): a `tier1` module, native only
  (`#[cfg(not(target_arch = "wasm32"))]`), with `register_tier1`. The
  loader dispatches on the manifest's tier: `Tier2Loader` becomes a
  directory loader for Tiers 1 and 2, and `session.reload_plugin` re-reads
  the rebuilt `.wasm`. New dependencies are `wasmtime` (native) and, if
  step 2 picks it, `wit-component` (native). The layer-lint edges table
  gains them.
- **CLI and app** (step 10): `--plugin` dispatches by tier everywhere.
  `arrix describe` shows a Tier 1 plugin's component and fuel, and `arrix
  test` runs the kit at Tier 1, where a fresh store per evaluation is the
  determinism check's fresh process.
- **Determinism** (step 7, `docs/CONCURRENCY-WASM.md` §Determinism): a
  plugin's result does not depend on its tier. `f64::sin`, `cos` and
  `tan` are the system libm natively and Rust's own libm on wasm32, so
  `gears` differed in the last place, so a plugin's math is
  `arrix_plugin_api::math` (`libm`), `gears` uses it, and the goldens
  naming a gear refresh once (**ADR-0036**, step 7, decided by the human).
- **wasm32** (step 11): `tier1` is gated out. A Tier 1 plugin named in a
  wasm build cannot load, and its features open frozen with their reason,
  as a Tier 2 plugin's do (`docs/PLUGINS.md` §Frozen fallback).
- No schema change: a document does not record its plugin's tier.

## Arris dependencies

None new. The kernel service is the 0.6 world's, implemented by
`arrix-kernel` on the pinned `arris` 0.8, and a component's kernel calls
are recorded like a Tier 0 plugin's, through the same `&mut dyn Kernel`.
Cancellation inside a kernel call is Arris's `Control` (A3, taken in C1).

## Findings

Step 2's probe (`crates/arrix-plugin-host/tests/probe_tier1.rs`, run with
`-- --nocapture` for its numbers), for step 3's ADR:

- **Target**: `wasm32-unknown-unknown`, already in the toolchain,
  componentised by the host with `wit-component` (12 ms for the 126 KB
  module). The component imports `arrix:plugin/types` and
  `arrix:plugin/kernel` and nothing else; the core module imports only
  the kernel functions it calls. `wasm32-wasip2` was not tried: its `std`
  imports WASI, which would only be refused.
- **`unsafe`**: no exception is needed. A probe SDK crate
  (`tests/probe-tier1/sdk`, the shape of the `guest` feature) and the
  plugin (`tests/probe-tier1/gears`, its one export line) both build at
  `forbid`, with no `allow` anywhere. `generate!` is a proc macro and the
  export glue expands only in the plugin's crate from the SDK's macro, and
  rustc does not report `unsafe_code` inside another crate's macro.
  Expanded from the plugin's own `export!`, the glue fails, as the
  backlog line said.
- **The world carries** `describe`, an `evaluate` error, and a spur
  through `extrude` and back as an owned `body`.
- **Times** (a dev test build, dependencies at opt-level 3): the guest
  rebuilds warm in 0.17 s; `Component::new` takes 231 ms; instantiating
  takes 0.1 ms; the spur's `evaluate` 0.11 ms.

Step 4: the crate stays 0.6.0, not 0.6.1. The equality test, `wire/`, the
Python SDK and the Tier 2 handshake all hold the WIT package version equal
to the crate's, and a component imports `arrix:plugin/kernel@<version>`, so
a patch bump would rewrite every generated wire file and break components
built a patch earlier for a change that does not touch the world.
`guest` is additive. `gears` builds as a core module in
`plugins/gears/tests/guest_build.rs` (`target/tier1-gears`, 7 s cold); the
probe's own SDK and workspace (`tests/probe-tier1`) are step 6's to
retire in favour of that build.

Step 6 (`crates/arrix-plugin-host/src/tier1`, `tests/tier1.rs`):

- **The world through the wire's codec.** The host uses wasmtime's
  dynamic API (`Linker::func_new`, `Val`), and `tier1/value.rs` maps a
  `Val` to the wire's JSON and back (ADR-0022 §3), so every value a
  component hands the host is decoded and checked by Tier 2's codec, and
  its kernel calls are served by Tier 2's `serve::kernel_call`, the
  capability check included. No second set of conversions; a value the
  codec refuses is `plugin.protocol`, as at Tier 2. A `body`'s resource
  representation is the evaluating kernel's own handle, so no table is
  kept.
- **A thread per evaluation.** A store's data is `'static` and the
  evaluator's kernel is borrowed, so the component runs on a scoped
  thread and asks for each kernel call over a channel, the evaluator's
  thread serving it, as a Tier 2 process asks over its pipe. The kernel
  stays on the evaluator's thread.
- **Epoch interruption is step 9's.** The engine has component model,
  fuel and NaN canonicalisation; a store has its fuel and the memory and
  table limits, a limit hit recorded so the trap that follows is
  `plugin.memory`. Fuel, memory and trap are classified now and tested in
  step 8.
- gear-on-plane through the component: the test binary runs in 7 s with
  the nested build cold, about 0.5 s warm. The test plugins and `gears`'
  `guest_build.rs` share `target/tier1-fixtures`
  (`tests/support/tier1.rs`, included by `#[path]`), and `probe_tier1.rs`
  now builds the real `gears` through it: the same 21 numbers of 891 differ,
  by at most 2 ulp.

Step 7 (`tests/tier1_parity.rs`, ADR-0036): with `gears` on
`arrix_plugin_api::math`, the two tiers agree to the bit on
`gear-on-plane` and the bracket (eval line, kernel calls, saved bytes),
and the probe's profile comparison reports 0 of 891 numbers differing.
`atan` was a fifth call site besides `sin`, `cos` and `tan`. The goldens
that moved: the CLI's `bracket`, `eval_assembly_*`, `eval_docs*`,
`eval_gear_on_plane`, `eval_slice*` and `eval_c2_accept`, the kernel's
`bracket-mass-properties` recipe, and `tests/docs/assembly-exchange`'s
frozen gear. Every changed number is within 17 ulp, or noise about an
exact zero; no status, count or key changed, and the Open CASCADE golden
did not move. The eval, sweep and summary goldens have no
`UPDATE_SNAPSHOTS` path: they are `arrix eval`'s output, written by hand.

Step 8 (`tests/tier1_sandbox.rs`, `tests/plugins/misbehave`): the loop ends
as `plugin.fuel`, a panic as `plugin.trap`, unbounded growth as
`plugin.memory`, and a kernel call under `kernel = false` as
`plugin.capability`, each beside a `fine` feature that evaluates. The
foreign import is a component made with `wasm-encoder` (a dev-dependency)
importing `wasi:clocks/monotonic-clock`, not `wit-component` over a widened
world: the refusal is on the import's name alone, and a hand-made
component says so more directly. Memory is reserved, not written
(`Vec::with_capacity`), or the fuel of filling it ends the call first.
A trap's diagnostic carries wasmtime's whole backtrace, and the panic's own
message is lost (the guest has no stderr); step 10 may shorten the first
and the SDK could route the second, neither is this step's.
